# 書き込み経路の CSP 実機確認 その 2 (W1 残り / W2 / W3)

[WRITE_TEST.md](WRITE_TEST.md) の 3 件 (往復 / 不透明度 / サムネイル削除) は
**全部問題なし**でした。ここはその続きで、**画素を書く経路**の確認です。

`samples/writetest/` に 8 ファイル生成しました。**CSP で開いて結果を教えてください。**

元ファイルはすべて `samples/opacity.clip` (300x400、下から 用紙 / レイヤー 1 /
レイヤー 2 の 3 枚。レイヤー 2 の不透明度 50%)。

書き込む画像は `samples/writetest/reference.png` に置いてあります。
**CSP の表示がこれと一致するか**を見てもらうのが目的です。特徴:

- 左→右で 赤→青、上→下で 緑が増えるグラデーション
- **中央の円 (直径 180px) がアルファ 96/255 の半透明**
- **四隅 40x40 が完全透明** (透明チェックが出るはず)
- 座標 255,256 に白の十字線 — **256px のブロック境界**をまたぐことの確認用

---

## 最重要: `BlockCheckSum` の 3 択

未解決の項目が 1 つあります。ブロック列の末尾にある **`BlockCheckSum`** の
算法が分かっていません。実測では

| | |
|---|---|
| 画素ありブロック | **必ず非ゼロ** (17,185 / 17,185 件) |
| 空ブロック | **必ずゼロ** (148,874 / 148,874 件) |

で、CRC32 / ~CRC32 / Adler32 / Fletcher32 / FNV-1a / CRC32C / 各種 sum・xor を
展開後・圧縮後・レコード全体に対して総当たりしましたが**どれも一致しません**。
CSP 独自のハッシュと見ています。

そこで **3 通りの書き方でファイルを作り分けました**。同じ内容のファイルが
3 つずつあるのはこのためです。

| 接尾辞 | 書いた内容 |
|---|---|
| `_zero` | 全ブロックのチェックサムに **0** を書く (CSP が実ファイルで書かない値) |
| `_crc32` | 展開後データの **CRC32** を書く (値としては「もっともらしい」が算法は違う) |
| `_none` | **`BlockCheckSum` / `BlockStatus` の欄ごと省略** |

> **どれが開けてどれがダメかで、CSP が検査しているのかどうかが分かります。**
> - 3 つとも開ける → **CSP は読み込み時に検証していない**。以後 `_zero` で書きます
> - `_zero` だけダメ → ゼロを不正値として弾いている。算法の特定が必須
> - `_none` だけダメ → 欄そのものが必須。値は見ていない
> - 3 つともダメ → 別の場所が壊れている。こちらで切り分けます

## 確認してほしいこと

### ① `w4_attrs.clip` — 属性まとめて変更 (W1 の残り)

SQLite の `Layer` を UPDATE しただけ。バイナリ領域は無変更 (サイズも元と同じ)。
レイヤー 2 に対して 3 つ同時に変えています。

- [x] **開けるか**
- [x] レイヤー名が **「改名テスト」** になっているか
- [x] 不透明度が **25%** になっているか (内部値 63/256)
- [x] 合成モードが **「乗算」** になっているか

> WRITE_TEST.md ② で不透明度 1 列は通っているので、ほぼ通る見込みです。
> 名前 (UTF-8 の文字列列) と合成モードの列番号確認が主目的。

### ② `w5_pixels_{zero,crc32,none}.clip` — 既存レイヤの画素を差し替え (W2)

**レイヤー 1 の中身を `reference.png` で丸ごと置き換え**たものです。
zlib 圧縮からブロックサブレコードの組み立てまで全部こちらで書いています。
ブロックが 4 枚 (256x256 が 2x2) に増えるので `ExternalChunk.Offset` も
全部計算し直しています。

- [ ] **開けるか** (3 ファイルそれぞれ)

crc32はエラー表示「レイヤ画像またはレイヤーマスクが破損しています」
開けるがレイヤー１がおかしい

- [x] **レイヤー 1 が `reference.png` と同じ絵になっているか**
- [x] **中央の円が半透明**になっているか (下のレイヤが透けるか)
- [x] **四隅 40x40 が透明** (チェック模様) になっているか
- [x] 白い十字線が **途切れたりズレたりしていないか** (ブロック境界の確認)
- [x] レイヤーパレットの**サムネイルが正しいか** (サムネイルは古いままにしてある —
      CSP が再生成するかの確認)

 青色の表示のまま
 追記するとその近辺の領域が更新される模様

- [ ] **そのレイヤに何か描き足して上書き保存 → 再度開いて壊れないか**

> ここが通れば **CLIP を書けるライブラリ**として成立します。
> 現状もっとも重要な検証です。

### ③ `w6_addlayer_{zero,crc32,none}.clip` — レイヤ新規追加 (W3)

**レイヤを 1 枚増やして最上段に置き、`reference.png` を入れた**ものです。
`Layer` は 57 列、`LayerThumbnail` は 43 列あって既定値の意味がほとんど
分からないので、**既存レイヤの行を丸ごと複製**して ID とリンクと画素だけ
差し替える方式にしました。ミップマップ 3 段 + サムネイルも複製しています。

- [x] **開けるか** (3 ファイルそれぞれ)
- [x] レイヤーパレットに **「追加レイヤ(zero)」等が最上段に**出ているか
- [ ] その中身が `reference.png` と同じか

全部透明で中身がない

- [x] **表示/非表示・不透明度・移動・描き込みが普通にできるか**
- [x] **上書き保存 → 再度開いて壊れないか** (ここが一番怖い)
- [x] レイヤを**削除**しても壊れないか

### ④ `w7_empty.clip` — 空レイヤの追加

同じ経路で **画素を入れずに** レイヤだけ足したもの。

- [x] **開けるか**
- [x] 「空レイヤ」が最上段にあり、**透明**になっているか
- [x] **そこに絵を描けるか**、描いて保存 → 再度開けるか

> 「CSP の新規レイヤと区別がつかないものが作れているか」の確認です。
> ここまで通れば **PSD → CLIP 変換の土台**ができます。

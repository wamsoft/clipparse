### 前 2 回で学んだ、失敗しないための原則

1. **下地の明るさをモードに合わせる。** 前回、覆い焼き系の矩形が「ほぼ白」の
   下地に乗ってしまい、式が飽和して複数の候補が同点になりました。
   - **覆い焼き / 加算** を見るときは → **暗い下地** (黒〜中間)
   - **焼きこみ** を見るときは → **明るい下地**
2. **色に関わるものは彩度のある下地で。** 前回 `adj_hsl.clip` の下地がグレーだったため、
   色相を回しても結果が一切変わらず、式を確定できませんでした。
3. **レイヤ名に条件を書く。** こちらは名前で対応を取ります。
4. **同じ設定で値だけ違うペア**を作ると、BLOB の差分でパラメータ位置が一発で分かります。

## 1. `glow.clip` — 「発光」有無の差 (最優先)

### 何を知りたいか

CSP には「覆い焼きカラー / 覆い焼き**(発光)**」「加算 / 加算**(発光)**」という
対になったモードがあります。前回の測定では **4 つとも同じ結果**になりました。
矩形が完全に不透明だったためです。

違いは**半透明のときのアルファの扱い**に出るはずで、ここが確定すると
CLIP→PSD 変換で「どのモードが可逆に移せるか」が決まります。

### 作り方

1. **新規作成: 800 x 600 px / カラー**

2. **下地レイヤ**: **暗いカラーグラデーション**を全面に。
   - 黒 → 中間色 (例: 濃い青や濃い緑) のグラデーション
   - **明るい部分を作らない**でください (覆い焼きが飽和して差が消えます)
   - 目安: 一番明るいところでも RGB 128 くらいまで

3. **矩形レイヤを 8 枚**。色はすべて **RGB(160, 96, 64)**。
   位置は重ならないように格子状 (4 列 x 2 行くらい)。

   **上段 4 枚 — アルファのグラデーションを持たせる**

   矩形の中で不透明度が 0% → 100% へ変化するようにしてください。
   作り方の一例:
   - 矩形選択ツールで選択範囲を作る
   - グラデーションツールを「**描画色から透明色**」にして、選択範囲の中を
     左から右へドラッグ

   これで 1 枚の矩形からアルファの全域が取れるので、
   アルファ依存の式をそのまま当てられます。

   | レイヤ名 | 合成モード | 不透明度 |
   |---|---|---|
   | `覆い焼きカラー_αグラデ` | 覆い焼きカラー | 100% |
   | `覆い焼き発光_αグラデ` | 覆い焼き (発光) | 100% |
   | `加算_αグラデ` | 加算 | 100% |
   | `加算発光_αグラデ` | 加算 (発光) | 100% |

   **下段 4 枚 — 不透明な矩形 + レイヤ不透明度 50%**

   こちらは単純な確認用です。矩形はベタ塗りのままで、
   **レイヤパレットの不透明度を 50%** にしてください。

   | レイヤ名 | 合成モード | 不透明度 |
   |---|---|---|
   | `覆い焼きカラー_不透明度50` | 覆い焼きカラー | **50%** |
   | `覆い焼き発光_不透明度50` | 覆い焼き (発光) | **50%** |
   | `加算_不透明度50` | 加算 | **50%** |
   | `加算発光_不透明度50` | 加算 (発光) | **50%** |

> 上段と下段で結果の傾向が違えば、「レイヤ不透明度」と「画素のアルファ」が
> 別扱いされているということが分かります。これも知りたい情報です。

## 2. `glow_folder.clip` — 下地が透明な場合 (余裕があれば)

「発光」の差が**下地の透明部分**に出る可能性もあるので、その確認用です。

1. `glow.clip` と同じ暗い下地を置く
2. **通常フォルダ** (通過ではない) を作る
3. そのフォルダの中に:
   - 一番下に、**キャンバスの左半分だけ**を塗ったレイヤ (通常合成)
   - その上に、**キャンバス全体**にかかる矩形を 4 枚 (上の 4 モード、不透明のまま)
     → 矩形の左半分はフォルダ内の絵の上、右半分は「フォルダ内では透明」の上に乗る

レイヤ名は `覆い焼きカラー_folder` のように `_folder` を付けてください。

## 3. 色相・彩度・明度 (`adj_hue30` / `adj_hue120` / `adj_sat` / `adj_val`)

### 共通の下地 (4 ファイルとも同じものを使ってください)

**虹色 + 明暗の下地**が必要です。前回はグレー階調だったため何も測れませんでした。

1. 新規作成: 400 x 400 px / カラー
2. 下地レイヤに:
   - **横方向に虹色のグラデーション** (色相が一周するもの。CSP の
     グラデーションセットに虹があればそれで OK)
   - **縦方向に明暗** (上が明るく下が暗い、など)
   - 彩度が 0 の部分 (灰色) が混じっていても構いません

この下地レイヤを作ったら、**同じファイルを 4 回コピーして**それぞれに
違う調整レイヤを載せるのが早いと思います。

### 作るもの

いずれも **調整レイヤ「色相・彩度・明度」を 1 枚**だけ載せます。

| 保存名 | 色相 | 彩度 | 明度 | レイヤ名 |
|---|---|---|---|---|
| `adj_hue30.clip` | **+30** | 0 | 0 | `色相30` |
| `adj_hue120.clip` | **+120** | 0 | 0 | `色相120` |
| `adj_sat.clip` | 0 | **+50** | 0 | `彩度50` |
| `adj_val.clip` | 0 | 0 | **+50** | `明度50` |

`adj_hue30` と `adj_hue120` は**値だけ違うペア**です。
2 つあると「30 という数値が度なのか 0〜255 の値なのか」が確実に決まります。

## 4. 単純な調整レイヤ (`adj_posterize` / `adj_invert`)

式が単純で検算しやすいものです。**下地はグレーの階段グラデーション (黒→白)**
で構いません (色に依存しないので)。

| 保存名 | 調整レイヤ | 設定 | レイヤ名 |
|---|---|---|---|
| `adj_posterize.clip` | ポスタリゼーション | 階調数 **4** | `ポスタリゼーション4` |
| `adj_invert.clip` | 階調の反転 | (設定なし) | `階調の反転` |

`adj_posterize` は前回作り漏れていたものです。
`adj_invert` はパラメータが無いはずなので、「パラメータ無しの調整レイヤの
BLOB がどうなるか」を確認する意味もあります。

## 5. トーンカーブ (`adj_tone1` / `adj_tone2`)

`filter.clip` に入っているトーンカーブは設定が分からないので測れませんでした。
**値の分かっている、できるだけ単純なカーブ**が欲しいです。

### 作り方

1. 新規作成: 400 x 400 px / カラー
2. 下地に**グレーの階段グラデーション (黒→白)**
3. 調整レイヤ「トーンカーブ」を 1 枚
4. **カーブは曲げず、左下の端点だけを上に動かす**
   - 入力 0 に対する**出力**を、`adj_tone1` では **64**、
     `adj_tone2` では **128** にする
   - 右上の端点 (入力 255 → 出力 255) は動かさない
   - 中間に点を追加しない

| 保存名 | 出力の下端 | レイヤ名 |
|---|---|---|
| `adj_tone1.clip` | **64** | `トーンカーブ 下端64` |
| `adj_tone2.clip` | **128** | `トーンカーブ 下端128` |

端点だけを動かした直線なので、結果は `out = 64 + v * (255-64)/255` の
ような一次式になるはずです。**2 つの差分**でカーブ点の格納形式が分かります。

数値を直接入力できない UI の場合は、だいたいの位置で構いません。
その場合は**レイヤ名に実際の値**を書いてください
(例: `トーンカーブ 下端62`)。

## 付録: これで何が決まるか

| サンプル | 決まること |
|---|---|
| `glow` / `glow_folder` | 「発光」有無の差 → **CLIP→PSD 変換の可逆性の見通し** |
| `adj_hue*` | 色相の単位 (度か 0..255 か) と回転の向き |
| `adj_sat` / `adj_val` | 彩度・明度パラメータの意味と適用式 |
| `adj_posterize` / `adj_invert` | 種別 7 / 6 の式。パラメータ無しの BLOB 形 |
| `adj_tone*` | 種別 3 (トーンカーブ) のカーブ点の格納形式 |

これらが入ると、**残るのはベクタのブラシエンジンだけ**になります
(ベクタは「CSP でラスタライズしてもらう」経路が
`vector_resterized.clip` で裏付け済みなので、当面は対応不要の方針です)。

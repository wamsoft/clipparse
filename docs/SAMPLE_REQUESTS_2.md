## 1. `blend2.clip` / `blend3.clip` — 合成モード

### 共通の作り方

1. **新規作成: 800 x 1000 px / 基本表現色 = カラー**
   (前回は 300x400 で矩形が重なりすぎたので広げます)

2. **下地レイヤ**を 1 枚。**明暗と彩度の両方に幅がある絵**にしてください。
   - 横方向にカラフルなグラデーション + 縦方向に明→暗、が理想
   - 面倒なら**適当なイラストを 1 枚貼るだけでも構いません**
   - 「色相 / 彩度 / カラー」の判定に下地の彩度が要るので、
     グレーだけの下地は避けてください

3. **矩形レイヤ**を 1 枚作る
   - 大きさ **150 x 150 px 程度**
   - 色は **RGB(160, 96, 64)** ← 濁った中間色にしてください
     (前回の RGB(0,5,255) のように 0 や 255 に張り付いた色だと、
      複数の合成式が同じ結果になって区別できません)
   - 不透明度は 100% のまま

4. あとは **「レイヤーを複製 → 移動 → 合成モードを変更 → レイヤ名を変更」**
   を必要な数だけ繰り返す
   - 位置は**格子状にだいたい並べる**感じで OK
   - 多少重なっても大丈夫です (重なっていない画素だけで判定します)
   - ただし各レイヤに**数百画素は他と重ならない部分**を残してください

5. **レイヤ名は CSP のメニューに出る合成モード名をそのまま**入力してください
   - 例: 合成モードを「焼き込みカラー」にしたレイヤの名前は `焼き込みカラー`
   - こちらは内部の数値とレイヤ名を突き合わせて同定するので、
     **名前さえ正確なら CSP の表記を知らなくても対応が取れます**
   - 名前が下の一覧と違っても構いません。**CSP の表示どおり**が正解です

### `blend2.clip` に入れる 10 種

```
□ 焼き込みカラー
□ 焼き込み(リニア)
□ 減算
□ 暗
□ 比較(明)
□ 覆い焼きカラー     ← 特に重要
□ 加算               ← 特に重要
□ 明
□ ソフトライト
□ ハードライト
```

### `blend3.clip` に入れる 9 種

```
□ ビビッドライト
□ リニアライト
□ ピンライト
□ ハードミックス
□ 除外
□ 色相
□ 彩度
□ カラー

```

### メニューに無いモードがあったら

飛ばして構いません。逆に**上の一覧に無いモードがメニューにあったら、
それも足してください** (こちらの一覧が不完全な可能性があります)。

## 2. `passthrough.clip` — フォルダの「通過」

これはフォルダ専用モードなので単独ファイルにします。
**通過とそうでない場合で結果が変わる構成**が必要です。

1. 新規作成 (400 x 400 程度で構いません)
2. **下地レイヤ**にグラデーションを描く
3. **フォルダ A** を作り、合成モードを **通過** にする
   - 中にレイヤを 1 枚入れ、そのレイヤの合成モードを **乗算** にする
   - 矩形を 1 つ描く (画面の左半分あたり)
4. **フォルダ B** を作り、合成モードは **通常** のまま
   - 中にレイヤを 1 枚入れ、そのレイヤの合成モードを **乗算** にする
   - 矩形を 1 つ描く (画面の右半分あたり。A と重ならないように)
5. フォルダ名は `通過` / `通常` にしてください

A では乗算が下地まで効き、B ではフォルダ内で完結するはずです。
その差を見て「通過」の実装を決めます。

## 3. 調整レイヤ (`adj_*.clip`)

調整レイヤの効果は `Layer.FilterLayerInfo` という BLOB に入っていますが、
中身が未解読です。**設定値が分かっているファイル**があれば、
結果から逆算して数値の位置を特定できます。

### 共通の作り方

1. 新規作成 (400 x 400 程度)
2. **下地レイヤ**に、**明暗の幅が広い絵**を描く
   - グレーの階段状グラデーション (黒→白) が理想的です。検算しやすいので
3. その上に**調整レイヤを 1 枚**だけ作る
4. **レイヤ名に設定値を入れる** (下の表のとおり)
5. 保存

### 作るもの

| 保存名 | 調整レイヤの種類 | 設定 | レイヤ名 |
|---|---|---|---|
| `adj_binarize.clip` | 2値化 | しきい値 **128** | `2値化 128` |
| `adj_posterize.clip` | ポスタリゼーション | 階調数 **4** | `ポスタリゼーション 4` |
| `adj_bright.clip` | 明るさ・コントラスト | 明るさ **+50** / コントラスト **0** | `明るさ50` |
| `adj_bright2.clip` | 明るさ・コントラスト | 明るさ **+100** / コントラスト **0** | `明るさ100` |
| `adj_hsl.clip` | 色相・彩度・明度 | 色相 **+30** / 彩度 0 / 明度 0 | `色相30` |

**2値化とポスタリゼーションが特に有効**です。式が単純なので、
出力から設定値を確実に逆算できます。

`adj_bright` と `adj_bright2` は**同じ種類で値だけ違う**のがポイントです。
2 ファイルの BLOB を差分すると、どのバイトが「明るさの値」かが一発で分かります。

## 4. `vector_rasterized.clip` — ベクタの確認用 (軽いもの)

ベクタレイヤは調べた結果、**ラスタを一切保存していませんでした**
(テキストと違い、外接矩形のラスタすら無くサムネイルだけ)。描くには
ブラシエンジンの実装が必要で、今の段階では割に合いません。

そこで「**変換前に CSP 側でラスタライズしてもらう**」という実用経路を
裏付けたいので、その確認用に 1 枚だけお願いします。

1. 新規作成 (400 x 400 程度)
2. ベクターレイヤを 1 枚作り、線を 2〜3 本描く
3. そのレイヤを右クリック →「**レイヤーのラスタライズ**」
4. 保存

ラスタライズ後に普通のラスタレイヤとして読めれば、この経路が確定します。

## 付録: なぜこれが要るか

- **合成モード** — 現状 8 種だけ実測同定済みです (乗算・スクリーン・オーバーレイ・
  比較(暗)・差の絶対値・輝度・覆い焼き(発光)・加算(発光))。残りが埋まると
  合成の再現と CLIP→PSD 変換の両方が進みます。

- **「覆い焼きカラー」「加算」が特に重要な理由** — 前回の測定で、CSP の
  「覆い焼き**(発光)**」と「加算**(発光)**」が PSD の標準式 (color dodge /
  linear dodge) と**そのまま一致**してしまいました。当初は逆 (発光付きが
  CSP 固有) だと予想していたので、**PSD 変換で非可逆になるのはむしろ
  発光なしのこの 2 つ**ではないかと考えています。ここが確定すると
  変換の可逆性の見通しが立ちます。

- **調整レイヤ** — `filter.clip` は現状まったく合っていません。
  レイヤより下のすべてに効くので、これが入らないと本番ファイルの
  合成が合いません。

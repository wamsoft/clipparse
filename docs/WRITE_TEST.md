# 書き込み経路の CSP 実機確認 (フェーズ ③)

`samples/writetest/` に 3 ファイル生成しました。**CSP で開いて結果を教えてください。**
ファイルを読むだけでは正しさを検証できない唯一のフェーズです。

生成は `tools/clip_write.py`。**元ファイルは `samples/opacity.clip`** (300x400、
用紙 + レイヤー 1 + レイヤー 2 の 3 枚。レイヤー 2 の不透明度が 50%)。

---

## 確認してほしいこと

### ① `w1_roundtrip.clip` — 無変更の読み書き往復

こちらでファイルを完全に分解し、**構造から組み立て直した**ものです。
元ファイルと **sha256 が一致** することは確認済み (60 MB の `tama.clip` でも一致)。

- [ ] **開けるか**
- [ ] レイヤー 2 の不透明度が **50%** と表示されるか
- [ ] 見た目が元と同じか

バイト一致しているので開けて当然ですが、**ここが土台**なので念のため。

### ② `w2_opacity64.clip` — 不透明度だけ変更

**SQLite の `Layer.LayerOpacity` を 128 → 64 に UPDATE しただけ**です。
バイナリ領域には一切触っていません (ファイルサイズも元と同じ 245,361 B)。

- [ ] **開けるか**
- [ ] レイヤー 2 の不透明度が **25%** と表示されるか
- [ ] レイヤー 2 が元より薄く表示されるか

> **これが通れば「CSP が我々の書いた SQLite を受け入れる」確証**になります。
> W1 (属性編集) 全体 — 名前 / 表示・非表示 / 合成モード / クリッピング —
> が同じ経路なので、まとめて実用段階に入れます。

### ③ `w3_nothumb.clip` — サムネイルの実体を削除

レイヤのサムネイルキャッシュのチャンクを**丸ごと削除**したものです。
チャンクが減った分バイナリ領域が詰まるので、**`ExternalChunk.Offset` を
全部計算し直して**書き込んでいます (6 チャンク → 5 チャンク、600 B 減)。

- [ ] **開けるか**
- [ ] レイヤーパレットの**サムネイル画像が正しく表示されるか**
      (CSP が再生成してくれるか)
- [ ] 表示がおかしい場合、**何か操作すると直るか**
      (レイヤをクリック、拡大率を変える、など)
- [ ] 上書き保存するとサムネイルが復活するか

> **オフセット再計算が正しいことの検証**が主目的です。これが通れば
> W2 (画素の差し替え) の土台ができます。
>
> あわせて「サムネイルを CSP が再生成してくれるか」も分かります。
> **再生成してくれるならレイヤ追加の実装が大幅に楽になります**
> — 現状レイヤ 1 枚追加するのに 100% ミップとサムネイルの両方を
> 自前で作る必要がありますが、後者が要らなくなります。

## 開けなかった場合

エラーメッセージ (あれば) を教えてください。切り分けのため、
どのファイルがダメだったかだけでも分かれば十分です。

- ① がダメ → 分解・再構築のどこかが壊れている (最も重大)
- ① OK / ② がダメ → SQLite を書き換えると CSP が拒否する。
  ジャーナルモードやページ配置の違いを疑う
- ①② OK / ③ がダメ → オフセット再計算か、サムネイル欠落そのものが原因。
  切り分けはこちらでやります

### 途中で踏んだ罠 (記録)

`ExternalChunk.ExternalID` は **`BLOB` 宣言なのに値は TEXT** で入っています
(`typeof()` が `'text'`)。bytes を束縛して `UPDATE` すると **1 行もマッチせず、
黙って失敗**します。最初これでオフセットが更新されず壊れたファイルができました。
`tools/clip_write.py` は str を束縛し、更新後に行数を検算しています。

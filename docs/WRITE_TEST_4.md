## 分かったこと (報告のおかげで確定した 3 件)

### ① レイヤ追加の中身が透明だった原因 — **ID の格納型**

`extrnlid...` という 40 文字の同じ ID が、**テーブルごとに違う型で入って**いました
[実測: 33 ファイル・7,000 行超で例外なし]:

| 列 | 実際の格納型 |
|---|---|
| `Offscreen.BlockData` | **BLOB** |
| `ExternalChunk.ExternalID` | **TEXT** |

新しく作る行に文字列で入れていたので、**CSP は実体を見つけられず、
そのレイヤを全面透明として開いて**いました。こちらのリーダは型に寛容で
どちらでも読めてしまうため、**実機で開いてもらうまで気付けませんでした**。

> 既存レイヤの画素差し替え (w5) だけ正しく見えたのは、**既存の ID を
> そのまま使い回していた**からでした。報告のこの食い違いが決め手です。

### ② `_crc32` だけ「破損しています」と出た件 — **CSP は検査している**

これで `BlockCheckSum` の扱いが決まりました:

| 書いた値 | CSP |
|---|---|
| **0** | 正常 |
| CRC32 (算法違い) | **破損エラー** |
| 欄ごと省略 | 正常 |

**CSP は非ゼロの値を実際に照合していて、0 は「検査値なし」扱い**。
つまり**算法を解かなくても 0 を書けば実用になります**。以後 0 固定にしました。

### ③ サムネイルが青いままだった件 — **実体があると作り直さない**

[WRITE_TEST.md](WRITE_TEST.md) ③ で「実体を消せば CSP が作り直す」ことは
確認済みでしたが、**古い実体が残っていると作り直さない**と分かりました。
画素を書き換えたら**サムネイルの実体を落とす**ようにしました。

### ⑤ 追加でお願いしたいサンプル — `addlayer_csp.clip`

**CSP 側の「正解」が欲しい**です。手順:

1. `samples/opacity.clip` を CSP で開く
2. **ラスタレイヤを 1 枚追加**し、適当に線を描く
3. `samples/addlayer_csp.clip` として保存

これがあると、こちらが複製で作ったレイヤと **CSP が作ったレイヤを列単位で
突き合わせ**られます。今回の型の間違いのような「開くまで分からない差」を
機械的に洗い出せるようになります。

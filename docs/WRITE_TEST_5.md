## 分かったこと

### ① w9 / w10 が落ちた原因 — `Mipmap.MipmapCount`

**ミップ連鎖の段数を減らしたのに `MipmapCount` を更新していませんでした。**
CSP はその数だけ連鎖を辿ろうとして、存在しない段まで進んで落ちていたようです
(「ロード中の待ちが長い → 落ちる」がまさにそれ)。

| ファイル | キャンバス | 必要な段数 | `MipmapCount` | 結果 |
|---|---|---|---|---|
| `w8` | 1234x567 | 5 | 5 | **開けた** |
| `w9` | 300x400 | 3 | 5 | 落ちた |
| `w10` | 800x1000 | 4 | 5 | 落ちた |

**雛形 (1600x1200) と同じ 5 段になる w8 だけ無事だった**、というのが決め手でした。
こちらのリーダは `NextIndex = 0` で止まるので、この食い違いが見えていませんでした。

> 同じ穴に落ちないよう `tools/clip_validate.py` を新設しました。
> **CSP で開く前に参照整合性を機械的に検査**します
> (ミップ段数・閉路・孤児行・格納型・消えたレイヤへの参照など)。
> 実ファイル 33 本と生成物 8 本で通ることを確認済みです。

### ② サムネイルが青いままだった原因 — 世代番号

`addlayer_csp.clip` と突き合わせたところ、**`LayerThumbnail` の
`Thumbnail*NeedRefresh` (14 列)** だけが違いました:

```
CSP が足したレイヤ : 50
既存のレイヤ       : 5
```

0/1 のフラグではなく**世代番号**らしく (実測値は 0〜380 万まで散らばる)、
実体を消すだけでは足りませんでした。**CSP が新規レイヤに書く 50 を入れる**
ようにしました。

### ③ 起動直後だけ白かった原因 — `CanvasPreview`

`CanvasPreview` テーブルに**キャンバス全体の PNG** が入っていて、
**CSP は開いた直後これを表示**していました。雛形 (1600x1200 の白) が
そのまま残っていたので「最初だけ変な白い表示 → レイヤを触ると正しくなる」に
なっていたわけです。**合成し直して差し替える**ようにしました。

### おまけ: `Canvas.CanvasCurrentLayer` が消えたレイヤを指していた

PSD→CLIP で雛形のレイヤを消したあと、選択中レイヤの参照が宙に浮いていました。
生きているレイヤへ付け替えます。

## 参考: 実装側で確認済みのこと

| | |
|---|---|
| 参照整合性 | `clip_validate.py` が 8 ファイルすべてで異常 0 (実ファイル 33 本も通る) |
| ミップ段数 | `MipmapCount` = 実段数 を全レイヤで確認 |
| 画素 | w5 / w6 とも `reference.png` と max=0 |
| プレビュー | 4 ファイルとも `CanvasPreview` が合成結果と **max=0** |
| 自動テスト | `tests/test_write.py` 18 件 (段数・格納型・参照整合性の回帰込み) |

これまでに CSP で確定した「書く側の作法」:

1. `Offscreen.BlockData` は **BLOB**、`ExternalChunk.ExternalID` は **TEXT**
2. `BlockCheckSum` は **0** (非ゼロは照合される)
3. `Mipmap.MipmapCount` は**必ず段数と一致**させる
4. サムネイルは**実体を消し**、`Thumbnail*NeedRefresh` に **50**
5. `CanvasPreview` を**合成し直す**
6. `Canvas.CanvasCurrentLayer` を**生きたレイヤ**に向ける

# 書き込み経路の CSP 実機確認 その 3 (PSD → CLIP 変換)

[WRITE_TEST_2.md](WRITE_TEST_2.md) と**まとめて確認してもらって構いません**。
こちらは一段重い検証で、**キャンバスごとこちらで組み立てた `.clip`** です。

`samples/writetest/` に 4 ファイル追加しました。**CSP で開いて結果を教えてください。**

---

## 何をしているか

`samples/emptyimage.clip` (CSP で「新規」しただけの 1600x1200 のファイル) を
**雛形**にして、

1. キャンバスを PSD の寸法へ**作り替える** (ミップ連鎖の段数・各段の
   `Attribute` を全部作り直す)
2. PSD のレイヤツリーを**下から順に**積む (フォルダも作る)
3. 雛形の 用紙 / レイヤー 1 を消す

つまり **「レイヤを足す」より一段深く、キャンバスの寸法そのものを書き換えて**います。
`Layer` 57 列 / `Canvas` 35 列の既定値は分からないままなので、
**行を丸ごと複製して分かっている列だけ差し替える**方式です。

ミップ段数は実測則で組み立てています (`docs/CLIP_FORMAT.md` §2.3):
100% から半分ずつ縮小し、**ブロックグリッドが 1x1 になった段の次の段まで**。

## 確認してほしいこと

### ① `w8_psd2clip.clip` — **雛形と違う寸法** (1234x567)

CSP を経由していない PSD (こちらで生成) から作りました。
**雛形は 1600x1200 なので、寸法の作り替えが効いているか**が焦点です。

構成 (下から):

```
グループ (通過)
  背景グラデ    … 全面不透明のグラデーション
  赤い円 50%    … 中央の円だけ α=160、他は完全透明
```

- [x] **開けるか**
- [x] キャンバスサイズが **1234 x 567** と表示されるか
- [ ] レイヤーパレットが上の構成どおりか (フォルダの中に 2 枚)

グループ（透過）
　赤い円 50%    実際は100%通常で透明
  背景グラデ    実際は100%通常で透明
開いた直後は全体が白くぬられてるような表示だが一度レイヤ表示ON/OFFすると全部透明

- [ ] 赤い円が**半透明**で、円の外が**透明**になっているか
- [ ] **表示倍率を変えても絵が崩れないか** (縮小ミップ段は空にしてあるので、
      CSP が縮小表示のたびに作り直しているかを見たい)
- [ ] **上書き保存 → 開き直しても壊れないか**

> ここが通れば **PSD → CLIP 変換が実用になります**。
> 縮小段が空でも大丈夫かはこの確認でしか分かりません。

### ③ `w10_psd2clip_blend.clip` — 合成モード 19 種の往復

### ④ `w11_psd2clip_paper.clip` — 用紙レイヤを残した版

① と同じ内容で、**雛形の白い用紙レイヤを残した**もの。

- [x] **開けるか**

赤い円と背景グラデは正しくないです

- [x] いちばん下に **「用紙」** があり、白いか
- [x] 用紙の色を変えられるか (用紙レイヤとして機能しているか)

> それが CSP で用紙として扱われるかの確認です。

## 開けなかった場合

どのファイルがダメだったかだけで十分です。切り分けの見当:

- ①④ がダメ / ②③ は OK → **寸法の作り替え**が原因 (雛形と同じ 300x400・800x1000 の
  ②③ は寸法を変えていない)
- ②③ もダメ → レイヤの組み立てそのもの。[WRITE_TEST_2.md](WRITE_TEST_2.md) ③ の
  結果と突き合わせます
- 開けるが縮小表示が崩れる → **縮小ミップ段を空にしている**のが原因。
  その場合は自前で縮小画像を作って埋めます
